# security-check

초보자가 만든 HTML/JS 코드에서 자주 발생하는 4가지 보안 문제를 기계적으로 찾아내고, 심각도별로 정리해서 보여주는 스킬이다. 목적은 "지금 당장 고쳐야 하는 위험"과 "확인이 필요한 것"을 구분해서, 사용자가 커밋하기 전에 무엇부터 손대야 할지 바로 알 수 있게 하는 것이다.

## 언제, 무엇을 점검하는가

다음 4가지만 점검한다 (범위를 벗어나는 다른 보안 검사는 하지 않는다 — SQL 인젝션, 서버 사이드 인증 로직 등은 대상이 아니다):

1. **하드코딩된 비밀번호·API 키** — 변수/속성 이름에 password, secret, apiKey, token 등이 들어 있는데 실제 문자열 값이 그대로 대입되어 있는가. AWS/Google/GitHub/OpenAI/Slack 형식의 키 패턴이 코드에 그대로 노출되어 있는가.
2. **innerHTML XSS** — `.innerHTML = ...`에 고정된 문자열이 아니라 변수·사용자 입력이 이스케이프(escape/sanitize) 없이 그대로 들어가는가.
3. **console.log 민감 정보 노출** — `console.log`(및 debug/info/warn/error)가 비밀번호·토큰 등으로 보이는 값을 그대로 찍고 있는가.
4. **http:// 외부 요청** — `https://`가 아닌 `http://`로 외부 주소(요청, 리소스 로드 등)를 가리키고 있는가 (localhost/127.0.0.1은 로컬 개발용이므로 제외).

## 실행 방법

1. 점검할 파일 경로를 확인한다. `.html`, `.js` 파일 모두 대상이며 둘 다 같은 방식으로 검사한다. 사용자가 파일을 지정하지 않았다면, 최근 작업하거나 수정한 파일을 우선 후보로 삼고 애매하면 물어본다.
2. 번들된 스크립트를 실행한다. Python 표준 라이브러리(`re`)만 사용하므로 별도 설치가 필요 없다.

   ```bash
   python "<skill-dir>/scripts/check_security.py" expense.html
   ```

   여러 파일을 한 번에 점검하려면 경로를 이어서 나열한다: `check_security.py a.html b.js`
3. 스크립트는 파일마다 `summary`(심각도별 개수)와 `issues`(항목별 상세, `check`/`line`/`message`/`suggestion` 포함)가 담긴 JSON을 표준출력으로 반환한다. 이 JSON을 그대로 보여주지 말고, 아래 "결과 표시 형식"에 맞춰 사람이 읽기 좋은 보고서로 재구성한다.
4. 이 스크립트는 정규식 기반 휴리스틱이다. 완벽한 정적 분석기가 아니므로, 특히 🟡 항목은 "진짜 문제인지 코드 맥락을 봐야 하는 후보"로 취급하고, 명백히 오탐이라고 판단되면 사용자에게 그렇게 설명해도 된다. 반대로 스크립트가 놓칠 수 있는 패턴(예: 여러 줄에 걸쳐 조립되는 문자열)이 있다면, 눈으로 훑어보며 보충 확인을 해준다.
5. `issues`가 비어 있으면(`summary`의 세 값이 모두 0) 축하 메시지와 함께 "4가지 항목 모두 통과"라고 알려준다.

## 결과 표시 형식

아래 구조를 그대로 따른다. 항목이 없는 등급은 생략하지 말고 "해당 없음"으로 표시해 사용자가 4가지를 다 확인했다는 걸 알 수 있게 한다.

```markdown
## 🔒 security-check 결과 — <파일명>

### 🔴 심각 (n개)
- **[hardcoded-secret]** 12행: "PASSWORD"에 비밀번호로 보이는 값이 코드에 그대로 박혀 있습니다 ("1234").
  → 제안: 비밀값은 코드에 직접 쓰지 말고 환경변수나 별도의 비밀 관리 저장소에서 불러오세요.

### 🟡 주의 (n개)
- **[http-external-request]** 40행: ...
  → 제안: ...

### 🟢 제안 (n개)
- 해당 없음

---
요약: 🔴 1  🟡 1  🟢 0
```

- 모든 항목에 `line`이 있으므로 `N행:` 형태로 위치를 알려줘서 사용자가 바로 찾아갈 수 있게 한다.
- 여러 파일을 점검했다면 파일별로 이 블록을 반복하고, 맨 끝에 전체 합계를 한 줄 덧붙인다.
- 지적만 하지 말고 각 항목마다 스크립트가 제공하는 `suggestion`을 "→ 제안:" 줄로 함께 보여준다.
- 사용자가 수정까지 요청하면, 점검이 끝난 뒤 이어서 해당 파일을 직접 고쳐준다. 점검 자체는 고치지 않고 진단만 하는 단계다.

## 심각도를 나누는 기준

- 🔴 심각: 지금 당장 실제 피해로 이어질 수 있다 — 코드에 박힌 진짜 비밀번호/키, 이스케이프 없이 사용자 입력을 innerHTML에 꽂아 넣는 코드(XSS 실행 가능), console.log가 비밀번호/토큰 변수를 그대로 출력.
- 🟡 주의: 문제일 가능성이 있어 확인이 필요하다 — http:// 평문 요청(도청·변조 위험은 있지만 즉시 실행되는 코드 실행 취약점은 아님), console.log 인자에 민감한 이름이 섞여 있지만 실제로 값이 찍히는지는 맥락 확인이 필요한 경우.
- 🟢 제안: 이 스킬에서는 기본적으로 사용하지 않지만, 위 4가지에 해당하지 않는 관련 개선 여지를 발견하면 이 등급으로 덧붙여도 된다(예: sanitize는 하고 있지만 라이브러리가 오래된 경우).

이 기준은 스크립트 안에 이미 반영되어 있으므로, 결과를 전달할 때 이 등급을 바꾸지 말고 그대로 사용한다. 다만 스크립트가 놓친 명백한 문제를 직접 발견했다면, 같은 4가지 관점 안에서 같은 형식으로 추가해도 된다.
