# page-check

초보자가 만든 HTML 페이지에서 자주 놓치는 5가지 문제를 기계적으로 찾아내고, 그 결과를 심각도별로 정리해서 보여주는 스킬이다. 목적은 "고쳐야 할 것"과 "있으면 더 좋은 것"을 구분해서, 사용자가 무엇부터 손대야 할지 바로 알 수 있게 하는 것이다.

## 언제, 무엇을 점검하는가

다음 5가지만 점검한다 (범위를 벗어나는 다른 품질 검사는 하지 않는다):

1. **title 유무** — `<title>` 태그가 없거나 비어 있는가
2. **깨진 내부 링크** — `<a href="...">`가 가리키는 로컬 파일이 실제로 존재하는가, `#id` 앵커가 페이지 안에 실제로 있는가 (외부 URL, `mailto:`, `tel:` 등은 검사 대상이 아니다)
3. **이미지 alt** — `<img>`에 `alt` 속성이 있는가
4. **모바일 viewport** — `<meta name="viewport" ...>`가 있는가
5. **한글 인코딩(UTF-8)** — 파일이 실제로 UTF-8이고, `<meta charset="UTF-8">` 선언이 있는가 (한글 등 비ASCII 문자가 있는데 선언이 없으면 더 심각하게 취급한다)

## 실행 방법

1. 점검할 HTML 파일 경로를 확인한다. 사용자가 특정 파일을 지정하지 않았다면, 대화나 최근 작업에서 만든 `.html` 파일(예: `index.html`)을 우선 후보로 삼고, 애매하면 사용자에게 어떤 파일인지 물어본다.
2. 번들된 스크립트를 실행한다. 이 스크립트는 Python 표준 라이브러리(`html.parser`)만 사용하므로 별도 설치가 필요 없다.

   ```bash
   python "<skill-dir>/scripts/check_page.py" index.html
   ```

   여러 파일을 한 번에 점검하려면 경로를 이어서 나열한다: `check_page.py a.html b.html`
3. 스크립트는 파일마다 `summary`(심각도별 개수)와 `issues`(항목별 상세) 목록이 담긴 JSON을 표준출력으로 반환한다. 이 JSON을 직접 사용자에게 보여주지 말고, 아래 "결과 표시 형식"에 맞춰 사람이 읽기 좋은 보고서로 재구성해서 보여준다.
4. `issues`가 비어 있는 항목이면(`summary`의 세 값이 모두 0) 축하 메시지와 함께 "5가지 항목 모두 통과"라고 알려준다.

## 결과 표시 형식

아래 구조를 그대로 따른다. 항목이 없는 등급은 생략하지 말고 "해당 없음"으로 표시해 사용자가 5가지를 다 확인했다는 걸 알 수 있게 한다.

```markdown
## 📄 page-check 결과 — <파일명>

### 🔴 심각 (n개)
- **[title]** <title> 태그가 없습니다.
  → 제안: <head> 안에 페이지를 설명하는 <title>을 추가하세요.

### 🟡 주의 (n개)
- **[viewport]** 67행: ...
  → 제안: ...

### 🟢 제안 (n개)
- 해당 없음

---
요약: 🔴 1  🟡 2  🟢 0
```

- `line`이 `null`인 항목(예: title, viewport, encoding처럼 파일 전체에 걸친 문제)은 줄 번호를 붙이지 않는다.
- `line`이 있는 항목(img alt, 깨진 링크)은 `N행:` 형태로 위치를 알려줘서 사용자가 바로 찾아갈 수 있게 한다.
- 여러 파일을 점검했다면 파일별로 이 블록을 반복하고, 맨 끝에 전체 합계를 한 줄 덧붙인다.
- 지적만 하지 말고 각 항목마다 스크립트가 제공하는 `suggestion`을 "→ 제안:" 줄로 함께 보여준다. 사용자가 왜 문제인지, 어떻게 고치는지 한 번에 알 수 있어야 한다.
- 사용자가 수정까지 요청하면, 점검이 끝난 뒤 이어서 해당 파일을 직접 고쳐준다. 점검 자체는 고치지 않고 진단만 하는 단계다.

## 심각도를 나누는 기준

이 스킬은 "페이지가 아예 깨지거나 못 찾는 문제"와 "더 나아질 수 있는 여지"를 구분한다:

- 🔴 심각: 사용자 경험이 실제로 망가진다 — 제목 없음(탭/북마크/검색 노출 불가), 링크가 실제로 죽어 있음(404), 한글이 있는데 인코딩 선언이 없어 깨져 보일 위험
- 🟡 주의: 페이지는 동작하지만 접근성·모바일 대응이 떨어진다 — alt 없는 이미지, viewport 메타 없음, 앵커 id는 없지만 파일 자체는 존재하는 링크
- 🟢 제안: 있으면 더 좋지만 당장 문제는 아니다 — 빈 alt=""(장식용일 수도 있음), charset 메타가 있지만 위치가 늦음, 한글이 없는 페이지의 charset 누락

이 기준은 스크립트 안에 이미 반영되어 있으므로, 결과를 전달할 때 이 등급을 바꾸지 말고 그대로 사용한다.
